# Local-mirror proof (the safety net before any live write)

The mirror is for **proving correctness**, not for standing in for a live path you haven't
validated (do the preflight first). Once the live path is known, build a faithful local
double of the target and prove the sync there: idempotency, preservation, FK integrity, and
rollback — so the live run is boring.

## 1. A faithful target double

Translate ONLY the tables the sync touches, from the target's real schema (Prisma/SQL), into
`db/target-schema.sql`. Faithfulness that matters:
- the exact **columns the sync writes** (a missing column = a silent live failure),
- the **UNIQUE keys the upsert conflicts on** (`UNIQUE(route, lang)`, etc.),
- FKs for anything you attach (so orphans surface locally),
- enum types the columns use.
Everything the sync doesn't touch can be omitted. Types: `bigint GENERATED BY DEFAULT AS
IDENTITY`, `jsonb`, `text[]`, `timestamptz`, `CREATE TYPE … AS ENUM`.

## 2. Seed it like production — including preserve-canaries

Fill the double with:
- the **real snapshot rows** (a committed pull of the live table, if you have one),
- **2 synthetic "target-only" rows the source will never own** (e.g. `/portal/booking`, a
  `legacy-hero.jpg` asset). These are your **preservation canaries** — the sync must leave
  them untouched. This is what actually catches an over-eager delete.
- FK targets (packages/destinations) so attach-by-slug has something to hit.

## 3. Restart-if-down guard (sandbox reaps Postgres)

Before each DB step, ensure the cluster is up. Keep it a single simple command (compound
shell gets classifier-blocked); split if needed:
```bash
psql "postgresql://postgres@localhost:5432/postgres" -tAc "select 1" >/dev/null 2>&1 \
  || su postgres -c "$PG_BIN/pg_ctl -D $PGDATA -o \"-p 5432 -k $SOCK\" -w -l $PGDATA/pg.log start"
```
Init once with `initdb -A trust -U postgres` as the `postgres` user, in a dir that user can
traverse (NOT under a root-0700 path — put PGDATA under `/var/lib/postgresql/...`, socket in `/tmp`).

## 4. Prove it (bundle as a test that runs the real script)

Run the sync **twice** against the double, then assert:
- **replace**: matched rows now hold source content (round-trip a known value);
- **preserve**: the 2 canaries still present, untouched;
- **idempotency**: after run 2, row counts are stable, 0 duplicate `(key)`;
- **FK integrity**: 0 orphans;
- **rollback**: apply `rollback.sql`, counts return to the pre-sync state.

Isolate the test's DBs from any shared test DB (create dedicated `*_sync` / `*_local`
databases in `beforeAll`) so it can't race another suite. Drive the actual script via
`execFile('node', [scriptPath], {env})` so you test the real artifact, not a reimplementation.

## Representative shape (from a proven run)

```
before: content_pages=73 (71 real + 2 canary), assets=2 (canary)
apply : content_pages 73→86 (+13, ~63 updated, 10 preserved), assets 2→56 (+54, 2 preserved), 0 FK orphans
re-run: +0 inserted, 0 duplicates            ← idempotent
rollback: content_pages→73, assets→2         ← exact restore
```

Only after this passes do you flip the live trigger from `plan` to `apply`.
